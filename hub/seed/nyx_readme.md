# Как ты пишешь модули — читай перед первым apply_file_edit

Это твой личный чеклист, не для чужих глаз (в git не попадает). Следуй ему
буквально — не выдумывай структуру заново каждый раз, единообразие важнее
творчества здесь.

## Модуль = одна папка в modules/, всё своё внутри

Твой модуль запускается в СВОЁМ ОТДЕЛЬНОМ процессе (не в одном процессе с
хабом и не с другими модулями). Это значит:
- если твой код зависнет или упадёт в бесконечный цикл — упадёт только он,
  хаб и чат с тобой продолжат работать
- если он упадёт при старте (ошибка импорта, syntax) — увидишь это через
  read_file("shared/logs/hub.log"), сам хаб не пострадает
- любое глобальное состояние в переменных Python НЕ переживёт рестарт и не
  расшарено с другими модулями — если что-то нужно помнить, пиши в свою
  data/<имя>.db или JSON-файл внутри своей же папки, не полагайся на память
  процесса

```
modules/<имя>/
├── manifest.json      — обязателен
├── router.py          — обязателен, должен определять `router = APIRouter()`
├── requirements.txt   — если нужны сторонние пакеты (необязателен)
├── data/               — твоя собственная папка данных этого модуля (SQLite и т.п.)
└── logs/               — свой лог, не пиши в общий hub.log
```

Имя папки САМО становится префиксом API — папка `modules/notes/` доступна
на `/api/notes/...`. Никакого отдельного поля в manifest.json для этого не нужно.

## manifest.json — обязательные поля

```json
{
  "name": "Task Scope",
  "version": "0.1.0",
  "enabled": true,
  "status": "active",
  "description": "Задачи и канбан"
}
```

Если не хватает хотя бы одного из `name/version/enabled/status/description` —
apply_file_edit откажется писать файл и вернёт тебе ошибку. Проверяй перед
отправкой, не угадывай.

- `enabled: false` — модуль ВИДЕН в /api/modules (как выключенный), но не подключается.
  Это осознанно: "выключен" ≠ "удалён". Если нужно, чтобы карточка пропала совсем — не
  через enabled, а через delete_path (ниже).
- `status` — свободное поле для дашборда (`active`, `stub`, `broken`)

## router.py

```python
from fastapi import APIRouter

router = APIRouter()

@router.get("/ping")
async def ping():
    return {"message": "модуль жив"}
```

Перед записью синтаксис проверяется автоматически (ast.parse) — если файл
не парсится как валидный Python, запись отклоняется, старая версия остаётся
на месте. Оборачивай рискованные операции в try/except внутри самих роутов —
не давай одному упавшему эндпоинту ронять процесс.

## Что подхватывается на лету, а что нет

Правка `router.py`, `manifest.json` или `requirements.txt` — поднимает/пересобирает
ТОЛЬКО этот модуль (свой отдельный процесс), за пару секунд, БЕЗ рестарта хаба
целиком. Чат и все остальные модули продолжают работать без перерыва. Правка
любого другого файла внутри modules/ (данные, конфиги, твои собственные
facts.json/prompt.md) — применяется мгновенно.

## Если нужна библиотека

Допиши её строкой в `modules/<имя>/requirements.txt` — хаб сам поставит её и
поднимет этот модуль заново, тебе не нужно ничего "выполнять" самой, ты не
запускаешь pip напрямую.

## Если модуль отдаёт файл пользователю (картинка, трек, отчёт)

Пиши байты напрямую в modules/nyx/data/outbox/<имя> обычным Python-кодом
(`open(path, "wb").write(data)`) — не через apply_file_edit, он принимает
только текст. Файл появится в панели "⬡ файлы" интерфейса автоматически.

Если хочешь, чтобы файл показался прямо в переписке (картинка/аудио инлайн,
не только в панели снизу) — в ответе чата упомяни строкой вида
"[файл: имя.png]" — интерфейс сам отрисует превью. Для остальных типов
это просто превращается в кнопку скачать.

Всё в outbox (и в inbox) хранится месяц — хаб сам чистит протухшее
(core/cleanup.py), самому модулю ничего удалять не нужно.

## Данные модуля

Держи свою БД в `modules/<имя>/data/<имя>.db` (SQLite — этого достаточно для
личного хаба). Не плоди отдельные Dockerfile/сервисы в docker-compose ради
каждого модуля — все они живут внутри процесса hub. Исключение — модуль,
которому реально нужна сетевая изоляция (например, будущий VPN-туннель) —
для него отдельный контейнер оправдан, но это делается руками, не тобой.

## Зарезервированные имена — не создавай модуль с таким именем

- `nyx` — твоя же папка: memory.json/prompt.md/facts.json/replies.json — твоё
  содержимое, редактируй свободно. Но router.py и manifest.json в этой же
  папке — код твоего чата, они в write-денилисте apply_file_edit (см.
  core/tools.py): физически рядом, но поменять их можешь только через git,
  не через себя. Попытка перезаписать их вернёт ошибку, не молчаливый провал.
- `interface` — статика ЧАТА (index.html/app.js/style.css). НЕ трогай её никогда, ни ради
  своего модуля, ни ради чего-либо ещё.

## Как модуль появляется на главной странице

Единая модель, без исключений: любой твой модуль с включённым `enabled: true` в manifest.json
автоматически становится карточкой в сетке "модули" на главной (имя/описание/версия — прямо из
manifest.json). Клик по карточке открывает окно ПОВЕРХ страницы (модалку) с содержимым GET "/"
твоего router.py внутри iframe. Никакого отдельного "холста снизу" или специальных зарезервированных
имён для этого не нужно — "dashboard" не особое имя, просто ещё один модуль.

## Если модулю нужна своя страница (не только API)

НЕ редактируй modules/interface/ для этого. Вместо этого верни HTML прямо из своего же router.py:

```python
from fastapi.responses import HTMLResponse

@router.get("/", response_class=HTMLResponse)
async def page():
    return "<html>...своя страница...</html>"
```

Она откроется по адресу /api/<имя>/ (и в модалке при клике на карточку) — полностью изолированно,
ничего общего не задевает. Если разметки много — держи её как обычную Python-строку в router.py
или отдельным .html-файлом внутри своей же папки (modules/<имя>/templates/...), который router.py
читает и отдаёт сам.

## Главная страница хаба — как она устроена

Сверху — чат. Это modules/interface/ (index.html/app.js/style.css) — фиксированная защищённая
оболочка, она должна жить всегда. НЕ трогай её никогда, без исключений, ни ради своего модуля,
ни "аккуратно, рядом с чужим кодом".

Снизу — сетка карточек всех модулей (рендерит хаб сам из manifest.json). Клик по карточке —
модалка с iframe на страницу модуля, отдельный документ браузера: даже если внутри модуля будет
ошибка в JS — это не заденет ни чат, ни саму страницу хаба.

## Модуль из зоны риска

Если появится модуль с паролями/авторизацией/финансами — трогай аккуратно,
ошибка там дороже, чем в обычном CRUD.

## Как добавить новый модуль — по шагам

1. `apply_file_edit("<имя>/manifest.json", ...)`
2. `apply_file_edit("<имя>/router.py", ...)`
3. Готово — модуль поднимется сам за пару секунд, хаб и чат не прерываются

## Как править уже СУЩЕСТВУЮЩИЙ модуль

Не через apply_file_edit (перезапишет файл целиком, риск потерять то, что не трогали).
Сначала `read_file`, потом `patch_file(путь, old_str, new_str)` — заменяет только нужный
фрагмент. old_str должен встречаться ровно один раз; если совпадений 0 или больше —
добавь больше окружающего текста в old_str, чтобы совпадение стало уникальным.

## Как убрать модуль совсем (не просто выключить)

`apply_file_edit` умеет только создавать/перезаписывать — удалить файл или папку им
нельзя. Для полного удаления — `delete_path("<имя>")` (весь модуль) или
`delete_path("<имя>/файл")` (один файл). Не безвозвратно: переносит в
`modules/.trash/`, не стирает физически. `nyx/` и `interface/` через delete_path
не трогаются вообще, ни целиком, ни частично — вернёт ошибку.
